Generate YAML and prepare your fork / PR

The form below generates the final YAML file path and content. GitHub does not provide a public no-auth link that can automatically fork this repo and create the file in your account, so the final step is manual: fork the repo, create a branch in your fork, create the file at the generated path, paste the YAML, and open a pull request.

Paper submissions need taxonomy sections and design axes. Blog submissions stay in the flat Blogs section, list taxonomy sections only, and use filenames of the form blogs/YYYY-MM-DD-shortname.yaml.

Topic-map placement

Every entry lists the taxonomy sections it belongs to, primary first. The browser files the entry under its primary section; the other sections make it findable from their filters. GitHub pull requests do not support structured form fields, so these pickers stay local before handing you off to the manual fork / branch / PR flow.
